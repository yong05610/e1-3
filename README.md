# Mini NPU Simulator

2차원 숫자 패턴과 필터의 유사도를 MAC(Multiply-Accumulate) 연산으로 계산하는 Python 콘솔 학습 프로그램입니다. Python 3.8 이상과 표준 라이브러리만 사용합니다.

## 실행 방법

프로젝트 폴더에서 실행합니다.

```powershell
python main.py
```

메뉴에서 `1`을 선택하면 3×3 사용자 입력 모드, `2`를 선택하면 JSON 분석 모드가 실행됩니다. `data.json`은 `main.py`와 같은 폴더에 둡니다. 프로그램은 현재 작업 폴더가 달라도 소스 파일 위치를 기준으로 이 파일을 찾습니다.

## 구현 요약

- 사용자 입력 모드는 필터 A, 필터 B, 패턴을 각각 세 줄씩 입력받습니다. 각 줄은 공백으로 구분한 숫자 세 개여야 합니다. 형식이나 숫자 변환에 실패하면 해당 행을 다시 요청합니다.
- 필터를 입력한 뒤 행렬을 화면에 보여 주고, 패턴 입력과 결과를 이어서 처리합니다.
- `mac()`은 외부 수치 라이브러리 없이 중첩 반복문으로 같은 위치의 두 수를 곱하고 누적 합산합니다.
- JSON 모드는 `patterns`의 `size_N_idx` 키에서 N을 얻어 `filters.size_N`을 선택합니다. 배열 구조와 크기를 사례별로 확인하며, 한 사례가 잘못되어도 나머지 사례를 처리합니다.
- JSON의 `+` 및 `cross` 표기는 `Cross`로, `x` 표기는 `X`로 정규화합니다. 라벨은 공백과 대소문자 차이를 허용합니다.
- `classify()`는 기본 epsilon `1e-9`를 사용합니다. 두 점수 차이의 절댓값이 epsilon보다 작으면 `UNDECIDED`이며, JSON 사례는 동점일 때 expected와 무관하게 FAIL입니다.
- `benchmark_mac()`은 각 입력 쌍에 대해 MAC을 10회 호출해 평균 시간을 ms로 표시합니다. JSON 성능 측정은 3×3의 미션 예시 필터 쌍과 JSON에서 읽은 크기별 Cross/X 필터 쌍을 사용합니다.

## 결과 리포트

아래는 `python main.py`에서 `2`를 선택해 실행한 한 번의 실제 결과입니다. 실행 환경과 부하에 따라 시간은 달라집니다.

| 사례 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

실행 요약: 총 테스트 6, 통과 3, 실패 3.

- `size_5_1`의 입력 패턴에는 X 모양의 활성 값이 9개 있습니다. Cross 필터와 겹치는 활성 위치는 가운데 한 곳이며 가중치가 `0.9`라 점수는 `0.9`입니다. X 필터는 입력의 활성 위치 9곳마다 `0.1`을 주므로 수학적으로 `9 × 0.1 = 0.9`입니다. 부동소수점 계산 결과는 `0.8999999999999999`로 표시될 수 있지만 두 점수 차이는 epsilon보다 훨씬 작아 `UNDECIDED`입니다. 현재 사례는 `expected`가 `x`인데 실제 점수로는 동점이 나옵니다. 이 불일치가 의도적인 경계 사례인지 데이터 오류인지는 mission에 명시되어 있지 않습니다. `+`는 필터가 아니라 `expected`에 쓰이는 Cross의 다른 표기입니다.
- `size_13_2`는 두 점수가 사실상 같아 epsilon 동점 규칙에 따라 `UNDECIDED`이며 FAIL입니다.
- `size_25_1`도 점수 차이가 epsilon보다 작아 `UNDECIDED`이며 FAIL입니다.
- 나머지 세 사례는 판정이 정규화된 expected 라벨과 일치해 PASS입니다.
- `+`/`x` expected와 `cross`/`x` 필터 키를 표준 라벨로 통일해 라벨 표기 차이로 인한 비교 오류를 피합니다.
- 이번 FAIL은 라벨 파싱이나 행렬 크기 오류가 아니라, 데이터 점수 차이가 epsilon보다 작아 동점으로 분류된 결과입니다.
- 동점 정책을 적용하지 않고 작은 부동소수점 오차를 승자로 취급하면 실행 환경이나 수치 누적 차이에 민감해질 수 있습니다.
- 현재 출력은 동점 사례를 성공으로 간주하지 않으므로 expected가 있어도 판정이 불확실하면 FAIL로 보고합니다.

## 성능 분석과 시간 복잡도

한 번의 실제 실행에서 출력된 표입니다. 반복 횟수는 크기별 10회이며, 각 행의 연산 횟수는 N²입니다.

| 크기(N×N) | 평균 시간(ms, 10회) | 연산 횟수(N²) |
|---:|---:|---:|
| 3×3 | 0.003130 | 9 |
| 5×5 | 0.006390 | 25 |
| 13×13 | 0.032730 | 169 |
| 25×25 | 0.106970 | 625 |

`mac()`은 N행을 순회하고 각 행에서 N열을 순회하므로 각 호출에서 N×N개의 위치를 처리합니다. 따라서 위치별 곱셈과 누적 횟수는 N²이며 시간 복잡도는 O(N²)입니다. 표의 연산 횟수는 3×3에서 9회, 25×25에서 625회로 증가하며, 평균 시간은 해당 환경에서 관측한 값입니다. 반복 측정은 작은 작업에서 타이머와 인터프리터의 영향도 받으므로 시간 비율이 연산 횟수 비율과 정확히 일치한다고 해석하지 않습니다.

## 재현 방법

### 사용자 입력 예시

`python main.py` 실행 후 `1`을 선택하고 아래 행들을 순서대로 입력합니다.

```text
필터 A
0 1 0
1 1 1
0 1 0
필터 B
1 0 1
0 1 0
1 0 1
패턴
1 0 1
0 1 0
1 0 1
```

기대 점수는 A 1.0, B 5.0, 판정은 B입니다. 성능 시간은 실행마다 달라집니다. 행에 숫자를 두 개만 입력하거나 `a b c`처럼 숫자가 아닌 값을 입력하면 오류 안내 후 해당 행을 다시 입력받습니다.

### JSON 모드와 오류 처리

`python main.py` 실행 후 `2`를 선택하면 제공된 `data.json`의 여섯 사례를 동적으로 분석하고 성능 표와 합계를 출력합니다. 크기 오류 처리를 확인하려면 원본 파일 대신 사본을 만들어 한 사례의 행렬 행을 제거한 뒤, `run_json_mode(사본_경로)`를 호출합니다. 그 사례는 FAIL 사유와 함께 표시되고 나머지는 계속 분석됩니다. JSON 전체가 잘못된 경우에는 `JSON 분석 오류` 안내 후 traceback 없이 반환합니다. 원본 데이터를 수정하지 않는 것을 권장합니다.

아래 명령은 원본을 건드리지 않고 임시 JSON을 만들어 크기 오류와 전체 JSON 파싱 오류를 각각 재현합니다.

```powershell
python -B -c "import json,tempfile,os; from main import run_json_mode; d=json.load(open('data.json',encoding='utf-8')); d['patterns']['size_5_1']['input'].pop(); f=tempfile.NamedTemporaryFile('w',encoding='utf-8',suffix='.json',delete=False); json.dump(d,f); f.close(); run_json_mode(f.name); os.unlink(f.name)"
python -B -c "import tempfile,os; from main import run_json_mode; f=tempfile.NamedTemporaryFile('w',encoding='utf-8',suffix='.json',delete=False); f.write('{bad json'); f.close(); run_json_mode(f.name); os.unlink(f.name)"
```

## 과제 목표 이해

이 과제의 목적은 작은 숫자 배열을 분류하는 프로그램을 만드는 데서 끝나지 않습니다. MAC 점수로 두 필터와 입력 패턴의 유사도를 비교하고, 데이터 형식과 수치 오차를 고려해 결과를 판단하며, 계산량과 실패 원인을 설명하는 것이 학습 목표입니다.

### 1. MAC 연산과 AI에서의 역할

MAC은 Multiply-Accumulate의 약자로, 같은 위치의 값을 곱하고 그 결과를 누적해서 더하는 계산입니다. 패턴과 필터를 비교할 때 각 위치의 곱을 모두 더해 점수를 만듭니다. 이미지 인식 등 AI 계산에서는 이런 곱셈·누적이 대량으로 반복되므로 중요한 기본 연산입니다. 이 프로그램은 실제 이미지를 인식하거나 학습하는 AI가 아니라, 그 계산 원리를 작은 숫자 배열로 보여 주는 시뮬레이터입니다.

### 2. 패턴과 필터의 유사도 점수

입력 패턴과 Cross/X 필터의 같은 위치끼리 곱한 뒤 모두 더하면 각 필터의 점수가 됩니다. 점수가 큰 필터를 입력 패턴과 더 유사한 것으로 판정합니다. 예를 들어 점수가 Cross 5, X 1이면 Cross로 판정합니다. 이 점수는 유사도를 비교하기 위한 값이며, 일반적인 확률이나 정확도 백분율은 아닙니다.

### 3. JSON 키·라벨 규칙과 정규화

JSON의 패턴 키 `size_N_idx`에서 `N`을 읽어 해당 크기의 `size_N` 필터를 찾습니다. JSON에는 준비된 평가 사례의 입력 행렬과 `expected` 라벨이 들어 있습니다. 프로그램은 입력 패턴을 먼저 판정하고, 판정 결과를 정답과 비교해 PASS/FAIL을 표시합니다. `expected`의 `+`와 필터 키의 `cross`는 표준 라벨 `Cross`로, `x`는 `X`로 통일합니다. 이 정규화는 표기만 다른 같은 라벨을 올바르게 비교하기 위한 것입니다. 사용자 입력 기능은 별도로 3×3 패턴을 직접 받아 판정하며, JSON에 3×3 사례가 없어도 사용할 수 있습니다.

### 4. 부동소수점 오차와 epsilon 동점 정책

컴퓨터의 실수 계산은 표현·누적 과정에서 아주 작은 오차가 생길 수 있습니다. 그래서 점수가 근소하게 다르다는 이유만으로 한쪽을 승자로 고르지 않도록 두 점수 차이의 절댓값이 `1e-9`보다 작으면 동점(`UNDECIDED`)으로 처리합니다. JSON 평가에서는 판정이 `UNDECIDED`이면 `expected`가 있더라도 PASS가 아니라 FAIL입니다. 이는 라벨이나 입력 형식 오류와 구별해야 하는 수치 비교 결과입니다.

### 5. 크기별 성능과 O(N²)

`N×N` 배열에는 `N²`개의 위치가 있으므로 MAC 한 번은 각 위치를 처리합니다. 따라서 배열 한 변의 길이가 두 배가 되면 처리 위치 수는 네 배가 되고, 이 계산의 시간 복잡도를 O(N²)로 표현합니다. 과제에서는 크기별 MAC을 최소 10회 측정해 평균 시간을 내고, 연산 횟수와 함께 살펴봅니다. 평균은 일시적인 시스템 부하에 따른 측정값의 흔들림을 줄이는 데 도움이 되지만, 실행 시간은 환경에 따라 달라집니다.

### 6. 실패 원인 분리와 진단

FAIL을 보면 곧바로 MAC 로직이 틀렸다고 결론 내리지 않고 원인을 구분해야 합니다. JSON 키·배열 구조·행렬 크기가 잘못됐다면 데이터/스키마 문제, 계산이나 필터 선택이 잘못됐다면 로직 문제, 점수가 epsilon 안에서 비슷해 판정이 `UNDECIDED`라면 수치 비교 문제일 수 있습니다. 실패 사례의 식별자와 점수·판정·expected를 함께 확인해 원인을 찾고, 적절한 부분을 개선합니다. 현재 제공 사례의 세 FAIL은 모두 epsilon 동점 판정에서 발생한 것으로, 데이터 형식 오류나 MAC 구현 오류와는 다른 원인입니다.
