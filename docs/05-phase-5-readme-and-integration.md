# Phase 5 — README 작성 및 통합 마감

## 개발팀 지시서

먼저 docs/00-PRD-and-design.md, TASK.md, 앞선 phase 지시서와 보고서를 읽으세요. Phase 1~4는 PM 검증을 통과했습니다. 이번 요청으로 승인된 범위는 Phase 5뿐입니다. 다른 phase 기능이나 보너스 작업은 구현하지 마세요.

### 역할

- 개발팀은 제출물 README.md를 작성하고, 앞선 구현을 통합해 누락·오류가 있으면 이번 범위 안에서 수정합니다.
- PM은 개발팀 보고를 검토하고 코드와 실제 실행 결과를 독립 검증해 최종 수용 여부를 결정합니다.
- README의 측정값·판정·총계는 실제 코드 실행 결과만 기록합니다. 개발팀은 PM 검증 완료를 대신 선언하지 않습니다.

### 이번 단계 범위

- 루트 README.md에 다음을 작성합니다.
  - 실행 방법, 모드 선택, data.json 위치
  - 프로그램 흐름 및 구현 요약
  - 라벨 정규화 방법, MAC 반복문 계산 방식, epsilon 동점 정책
  - 실제 data.json 사례별 결과, 총/통과/실패 수와 FAIL 원인
  - FAIL이 0건인 결과라면 정규화·epsilon 정책과 검증이 그 결과에 기여한 이유
  - 실제 성능표와 실행 환경 의존성 설명
  - N×N에서 곱셈·누적이 N²회 발생하는 근거와 측정 결과의 연결, O(N²) 설명
  - 재현성: 사용자 입력 예시, JSON 실행 방법, 의도적 입력 오류 확인 방법
- README의 결과 리포트는 최소 10줄 이상 작성합니다.
- 현재 제공 data.json은 6개 패턴입니다. 참고 예시의 8건을 실제 결과로 쓰거나 하드코딩하지 않습니다.
- main.py, README.md, data.json 간 명령·파일경로·판정정책·결과 총계의 불일치를 확인합니다.
- 요구사항 누락이나 구현 오류를 발견하면 기존 승인 범위에서 필요한 수정만 합니다. 범위를 넓히는 기능 변경은 PM에게 먼저 보고합니다.
- 완료 보고서 docs/reports/phase-5-report.md를 작성합니다. README의 핵심 수치와 원인을 실제로 확인한 명령·출력 근거와 함께 기록합니다.

### 이번 단계에서 하지 말 것

- 보너스 기능 및 미션에 없는 기능
- 실제와 다른 PASS/FAIL, 시간 측정값, 성능 분석을 문서에 기록하는 일
- data.json 기대값 또는 원본을 바꾸는 일
- 승인되지 않은 대규모 구조 변경, 파일 삭제
- TASK.md의 상태 변경(PM이 독립 검증 후 갱신함)
- PM 검증 없이 프로젝트를 최종 완료 처리하는 일

### 완료 확인 기준

- README.md에 실행·구현·결과·성능 복잡도·재현성 정보가 모두 있습니다.
- 결과 리포트가 10줄 이상이며 실제 출력과 일치합니다.
- PASS/FAIL 총계와 실패 케이스 원인이 실제 JSON 실행과 일치합니다.
- 성능표의 크기·N²·측정 반복 기준이 Phase 4 구현과 일치합니다.
- 사용자 입력 및 JSON 모드가 통합 상태로 실행됩니다.
- 잘못된 행 입력 재시도, 사례 단위 JSON FAIL, 전체 JSON 오류 처리가 기존 요구대로 유지됩니다.
- 개발팀은 변경점·직접 확인한 실행 명령과 결과·미해결 사항을 보고서에 기록합니다.

5. 오류/회귀 시나리오와 실제 결과

7. 미완료 사항, 알려진 문제, PM 결정 요청
8. 승인 범위 밖 변경 여부

Phase 5 구현과 보고서만 마친 뒤 멈추세요. 개발팀은 Phase 5 완료를 보고하고 PM의 최종 독립 검증을 기다리세요.
