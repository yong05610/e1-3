# Phase 2 — 사용자 입력 3×3 모드

## 개발팀 지시서

먼저 docs/00-PRD-and-design.md, TASK.md, docs/01-phase-1-core.md 및 docs/reports/phase-1-report.md를 읽으세요. Phase 1은 PM 검증을 통과했습니다. 이번 요청으로 승인된 범위는 Phase 2뿐입니다. 다른 phase 기능이나 보너스 작업은 구현하지 마세요.

### 목적

사용자가 콘솔에서 3×3 필터 A/B와 패턴을 입력하고, Phase 1 함수로 MAC 점수와 판정을 계산해 결과를 확인하게 합니다.

### 이번 단계 범위

- 기존 main.py를 먼저 살펴 Phase 1 구현을 보존하고 그 위에 기능을 추가합니다.
- 프로그램 제목과 모드 선택 메뉴를 표시합니다.
- 사용자 입력(3×3) 모드를 선택하면 필터 A, 필터 B, 입력 패턴을 순서대로 받습니다.
- 각 행렬은 3행이며, 각 행은 공백으로 구분된 숫자 3개를 받습니다.
- 행의 숫자 개수가 3개가 아니거나 숫자 파싱에 실패하면 요구 형식을 안내하고 해당 행을 다시 입력받습니다. 잘못된 입력으로 프로그램이 비정상 종료되면 안 됩니다.
- 필터 A와 B 입력을 모두 받은 뒤 저장된 행렬을 간단히 확인할 수 있게 보여 준 후 패턴을 입력받습니다.
- Phase 1의 mac()과 classify()를 재사용해 점수와 A/B/판정 불가 결과를 계산합니다. 계산 로직을 중복 작성하지 않습니다.
- MAC 함수 호출 구간만 perf_counter 등 표준 라이브러리로 최소 10회 반복 측정하고 평균 시간을 ms 단위로 표시합니다. 입력·출력 시간은 측정에 포함하지 않습니다.
- 메뉴의 JSON 분석 항목은 표시하되, 이번 단계에서 JSON 처리는 구현하지 않습니다. 선택 시 아직 제공되지 않는 기능임을 안내하고 프로그램을 정상적으로 마칩니다.
- 메뉴·입력·표시 책임을 함수로 나눠 읽기 쉽게 구현합니다. 기존 함수 이름과 설계 문서가 충돌하면 임의 변경 전에 PM에게 알립니다.

### 이번 단계에서 하지 말 것

- data.json 로딩, 필터 크기 선택, 라벨 정규화, 사례별 PASS/FAIL
- 5×5, 13×13, 25×25 성능표
- README 작성, 최종 결과 리포트
- 클래스 도입, 외부 라이브러리, 보너스 기능
- Phase 1의 검증된 MAC·판정 정책 변경
- 승인되지 않은 파일 삭제, 이름 변경, 대규모 재구성
- TASK.md의 상태 변경(PM이 개발 보고를 독립 검증한 뒤 갱신함)

### 완료 확인 기준

- 모드 1을 선택해 필터 A/B와 패턴을 입력하면 두 점수, 평균 시간(ms), 판정 A/B/판정 불가가 출력됩니다.
- 지시서의 십자가/X 3×3 예시 입력으로 점수와 판정이 올바르게 표시됩니다.
- 같은 점수 또는 차이가 1e-9보다 작은 점수는 판정 불가입니다.
- 행의 숫자 수 불일치와 숫자 파싱 오류에서 안내 후 해당 행을 재입력받습니다.
- 성능 측정은 MAC 호출만 10회 이상 반복하고 평균을 계산합니다.
- JSON 메뉴 항목은 보이지만 JSON 기능을 앞서 구현하지 않습니다.
- 자동 테스트 파일이나 테스트 프레임워크는 추가하지 않습니다. 수동 확인 명령과 실제 결과를 보고서에 남깁니다.
