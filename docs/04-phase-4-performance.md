# Phase 4 — 크기별 성능 분석

## 개발팀 지시서

먼저 docs/00-PRD-and-design.md, TASK.md, 앞선 phase 지시서와 보고서를 읽으세요. Phase 1~3은 PM 검증을 통과했습니다. 이번 요청으로 승인된 범위는 Phase 4 성능 분석뿐입니다. 다른 phase 기능이나 보너스 작업은 구현하지 마세요.

### 목적

실제 mac() 호출을 크기별로 반복 측정해 평균 실행 시간(ms)과 N² 연산 횟수를 표시합니다.

### 이번 단계 범위

- Phase 2의 benchmark_mac()을 재사용하거나 필요한 부분만 최소 수정합니다. 측정 코드를 불필요하게 중복 구현하지 않습니다.
- 측정 크기는 3×3, 5×5, 13×13, 25×25이며, 각 크기별 MAC 호출을 최소 10회 반복합니다.
- 반복 수는 사용자가 조정할 필요가 없도록 명확한 기본값(최소 10)으로 관리합니다.
- perf_counter 등 표준 라이브러리로 MAC 함수 호출 구간만 측정합니다. 입력, 출력, JSON 읽기, 패턴 준비 시간은 측정에서 제외합니다.
- JSON 모드에 성능 분석 표를 추가하고, 크기(N×N), 평균 시간(ms), 연산 횟수(N²) 열을 표시합니다.
- JSON에는 5×5, 13×13, 25×25만 있으므로 JSON 성능표의 3×3 행렬은 미션에 나온 고정 십자가와 X 예시 행렬을 성능 측정용 입력으로 사용합니다. 이는 벤치마크용 상수이며 새 패턴 생성 기능으로 확장하지 않습니다.
- 5×5, 13×13, 25×25의 벤치마크 입력은 JSON에서 이미 로드한 해당 크기의 필터/행렬을 사용합니다. 각 크기마다 동일한 방식으로 MAC 호출 시간을 측정합니다.
- JSON 사례별 PASS/FAIL 결과를 계산한 뒤 성능표와 합계가 표시되도록 연결합니다. I/O가 벤치마크 구간에 포함되지 않게 합니다.
- 사용자 입력 모드의 기존 3×3 평균 시간 출력은 유지합니다.
- 시간은 실행 환경에 따라 변하므로 실제 측정값을 출력하고 예시값을 하드코딩하지 않습니다.

### 이번 단계에서 하지 말 것

- README 작성과 O(N²) 보고서 문장(Phase 5)
- 1차원 배열 최적화, 패턴 생성기 등 보너스 기능
- PASS/FAIL, 라벨, epsilon 정책 변경
- data.json 원본 수정
- 외부 라이브러리, 자동 테스트 파일/프레임워크
- 승인되지 않은 사용자 입력 흐름 또는 JSON 스키마 변경
- TASK.md의 상태 변경(PM 독립 검증 후 PM이 갱신함)

### 완료 확인 기준

- JSON 모드 성능표에 3×3, 5×5, 13×13, 25×25가 모두 한 번씩 출력됩니다.
- 연산 횟수는 각각 9, 25, 169, 625입니다.
- 평균 시간은 크기별 MAC 호출을 10회 이상 측정해 계산하며 I/O 시간은 포함하지 않습니다.
- 사용자 입력 모드는 기존처럼 A/B별 3×3 평균 시간을 계속 출력합니다.
- 기존 6개 데이터 사례의 PASS/FAIL 총계가 Phase 3 결과와 같습니다.
- 측정값은 실행 시 달라지고 코드에서 고정값으로 만들지 않습니다.
- 별도 패턴 생성 기능이나 자동 테스트 파일을 추가하지 않습니다.
